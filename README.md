# فَهْدَار | FAHDAR

> **أفكارك تبدأ من هنا.** — التطبيق الشخصي التقني الرسمي لـ **فهد مبارك**.

تطبيق جوال حقيقي (React Native + Expo + TypeScript) يعمل على **Android وiOS** (وليس WebView)، مع خادم Supabase
(PostgreSQL + Auth + Storage + Realtime + Edge Functions). يتيح للزوار التعرف على فهد ومشاهدة أعماله، ويتيح
للمستخدمين المسجلين إرسال طلبات برمجية ومتابعتها، والحصول على استشارات تقنية محدودة، مع لوحة إدارة خاصة بالمالك.

## قاعدة البيانات والأمان

الملف: `supabase/migrations/20261115000000_fahdar_core.sql`

| الجدول | الغرض | من يقرأ / يكتب |
|---|---|---|
| `profiles` | حساب كل مستخدم + الدور (`user`/`owner`) | المستخدم يقرأ نفسه ويعدّل (الاسم/الجوال/الصورة/اللغة) فقط؛ المالك يقرأ الجميع |
| `owner_profile` | ملف فهد العام (صف واحد) | الجميع يقرأ؛ المالك يعدّل |
| `projects` · `achievements` · `site_updates` | معرض الأعمال والإنجازات والتحديثات | المنشور للجميع؛ المسودات والكتابة للمالك |
| `project_requests` | طلبات البرمجة + رقم فريد | صاحب الطلب والمالك؛ الحالة يغيّرها المالك فقط |
| `request_messages` | محادثة الطلب وخط الحالات | أطراف الطلب |
| `consultations` · `consultation_messages` | الاستشارات ورسائلها | أطرافها — **الكتابة عبر دوال الخادم فقط** |
| `usage_limits` | استشارات إضافية يمنحها المالك لمستخدم في شهر معيّن | المالك |
| `attachments` | بيانات المرفقات (الملفات في حاوية خاصة) | الرافع وأطراف الطلب/الاستشارة والمالك |
| `notifications` · `push_tokens` | الإشعارات ورموز الأجهزة | المستخدم نفسه؛ الإنشاء من الخادم فقط |
| `admin_settings` | تشغيل/إيقاف الطلبات والاستشارات والحدود | الجميع يقرأ؛ المالك يعدّل |
| `activity_logs` | سجل النشاطات (يُكتب بالمحفّزات) | المالك فقط |

**ضمانات الأمان (كلها مختبرة):**
- RLS مفعّل على **كل** الجداول، والصلاحيات تبدأ من الصفر (`revoke all`) ثم تُمنح بالأعمدة المطلوبة فقط.
- **لا يمكن ترقية النفس إلى مالك**: عمود `role` غير قابل للكتابة من العميل (صلاحيات أعمدة + محفّز حماية)، والترقية فقط عبر SQL من لوحة Supabase.
- **حدود الاستشارات لا يمكن التلاعب بها**: لا توجد صلاحية INSERT مباشرة؛ `start_consultation` و`send_consultation_message` دوال `SECURITY DEFINER` تستخدم أقفالاً (advisory lock / `FOR UPDATE`) — اختُبر إرسال 4 طلبات متزامنة فقُبل 2 فقط.
- العدّ الشهري يُحسب من تواريخ الإنشاء في المنطقة الزمنية المحددة (افتراضياً `Asia/Riyadh`)، فالتجديد تلقائي ولا يوجد عدّاد يمكن العبث به.
- المرفقات في حاوية **خاصة** (`attachments`)، كل مستخدم يرفع داخل مجلده فقط، والقراءة بروابط موقّعة قصيرة العمر. أنواع الملفات والحجم يُتحقق منها في الخادم.
- حالة الطلب ورقمه وتاريخه يفرضها الخادم مهما أرسل العميل.
- **لا مفاتيح إدارة في التطبيق**: التطبيق يحمل المفتاح العام فقط. مفتاح `service_role` موجود فقط داخل Edge Functions.
- حساب المالك محمي من الحذف العرضي من داخل التطبيق.

## التشغيل محلياً

المتطلبات: Node 20+، Docker، [Supabase CLI](https://supabase.com/docs/guides/cli).

```bash
npm install
cp .env.example .env              # للتطوير المحلي ضع قيم `supabase start`
npm run db:start                  # يشغّل Supabase محلياً ويطبّق الهجرات
npm run functions:serve           # (اختياري) Edge Functions — يحتاج supabase/functions/.env
npm start                         # ثم امسح رمز QR بتطبيق Expo Go أو اضغط a / i
```

ملف `supabase/functions/.env` (لا يُرفع إلى Git):
```
PUSH_WEBHOOK_SECRET=أي-نص-سري-طويل
```

> ملاحظة: الإشعارات الفورية (Push) لا تعمل في Expo Go على Android منذ SDK 53؛ استخدم نسخة تطوير (`eas build --profile development`).

## الربط بمشروع Supabase حقيقي

> ⚠️ **أنشئ مشروع Supabase جديداً خاصاً بفهدار.** لا تطبّق الهجرة على مشروع الموقع الحالي (`jujkckphabzsfjcodefy`)،
> لأنه يحتوي جداول بالأسماء نفسها (`profiles`, `consultations`, `notifications`, `activity_logs`) ببنية مختلفة.

1. أنشئ مشروعاً من [supabase.com/dashboard](https://supabase.com/dashboard).
2. اربط وطبّق المخطط:
   ```bash
   supabase login
   supabase link --project-ref <PROJECT_REF>
   supabase db push
   ```
3. انشر الدوال وأضف أسرارها:
   ```bash
   supabase functions deploy push-dispatch --no-verify-jwt
   supabase functions deploy delete-account
   supabase secrets set PUSH_WEBHOOK_SECRET=<نص-سري-طويل>
   # اختياري إذا فعّلت "Enhanced push security" في Expo:
   supabase secrets set EXPO_ACCESS_TOKEN=<token>
   ```
4. **Authentication → URL Configuration**: أضف إلى Redirect URLs:
   `fahdar://**` (وأثناء التطوير `exp://**`).
5. **Authentication → Email Templates**: انسخ محتوى
   `supabase/templates/recovery.html` إلى قالب *Reset Password* و`confirmation.html` إلى *Confirm signup*.
   (قالب الاستعادة يحتوي `{{ .Token }}` ليعمل إدخال الرمز داخل التطبيق.)
6. ضع القيم العامة في `.env` (أو في متغيرات EAS):
   ```
   EXPO_PUBLIC_SUPABASE_URL=https://<PROJECT_REF>.supabase.co
   EXPO_PUBLIC_SUPABASE_ANON_KEY=<publishable / anon key>
   ```

## تعيين المالك (فهد)

1. سجّل حساب فهد من التطبيق كأي مستخدم.
2. في **SQL Editor** بلوحة Supabase نفّذ:
   ```sql
   select private.promote_to_owner('fahad@example.com');  -- بريد فهد
   ```
3. أعد فتح التطبيق: سيظهر زر «لوحة الإدارة» في «حسابي».

هذه هي الطريقة الوحيدة للترقية؛ الدالة غير متاحة لأي مستخدم عبر الـ API.

## الإشعارات الفورية Push

المسار: صف جديد في `notifications` ← محفّز `private.dispatch_push` ← `pg_net` ← Edge Function `push-dispatch` ← Expo Push API ← الجهاز.

1. اربط التطبيق بـ EAS (مرة واحدة): `npx eas-cli@latest init` — يضيف `extra.eas.projectId` إلى `app.json`.
2. Android: أضف بيانات FCM v1 إلى EAS (`npx eas-cli credentials`) — [الدليل](https://docs.expo.dev/push-notifications/fcm-credentials/).
   iOS: يتولى EAS مفتاح APNs أثناء البناء.
3. فعّل الربط من قاعدة البيانات (SQL Editor):
   ```sql
   insert into private.app_config (key, value) values
     ('push_function_url', 'https://<PROJECT_REF>.supabase.co/functions/v1/push-dispatch'),
     ('push_webhook_secret', '<نفس PUSH_WEBHOOK_SECRET>')
   on conflict (key) do update set value = excluded.value;
   ```
4. في التطبيق: «حسابي ← الإعدادات ← تفعيل الإشعارات». يُسجَّل رمز الجهاز تلقائياً بعد ذلك عند كل دخول، ويُحذف عند الخروج.

## بناء نسختي Android وiOS

البناء عبر **EAS Build** (سحابي — لا يحتاج Android Studio أو Xcode محلياً):

```bash
npm i -g eas-cli            # أو استخدم npx eas-cli@latest
eas login
eas init                    # أول مرة فقط
# أضف EXPO_PUBLIC_SUPABASE_URL و EXPO_PUBLIC_SUPABASE_ANON_KEY من:
# expo.dev ← المشروع ← Environment variables (بيئتي preview و production)

npm run build:preview       # APK للتجربة المباشرة على Android
npm run build:android       # AAB للنشر على Google Play
npm run build:ios           # IPA للنشر على App Store (يتطلب حساب Apple Developer)

eas submit -p android       # رفع إلى Google Play
eas submit -p ios           # رفع إلى App Store Connect / TestFlight
```

المعرّفات: `com.fahadmubarak.fahdar` (Android وiOS) — غيّرها في `app.json` قبل أول بناء إن رغبت.
بناء محلي بديل (يتطلب Android SDK / Xcode): `npx expo run:android` · `npx expo run:ios`.

## الاختبارات وما تم التحقق منه

```bash
npm run typecheck           # TypeScript strict — بلا أخطاء
npm run lint                # ESLint (expo + React Compiler rules) — بلا أخطاء
npm run test:db             # 18 اختبار تكامل على Supabase حقيقي (يتطلب supabase start + functions:serve)
NODE_PATH=$(npm root -g) node tests/e2e-web.cjs   # اختبار الواجهة الشامل (يتطلب npx expo start --web)
```

**تم التحقق منه فعلياً** على نسخة Supabase محلية كاملة (Postgres + Auth + Storage + Realtime + Edge Runtime):
- منع الترقية الذاتية، عزل البيانات بين المستخدمين، منع الكتابة المباشرة، حماية لوحة الإدارة من الخادم.
- حد الاستشارتين شهرياً (حتى مع طلبات متزامنة)، حد الرسائل الخمس، تمديد المالك للحد، منح استشارات إضافية، الإغلاق.
- رقم الطلب الفريد، الحالات، الإشعارات المترجمة حسب لغة المستخدم، سجل النشاطات، إيقاف الطلبات مؤقتاً.
- المرفقات: الرفع للمجلد الخاص فقط، منع الأنواع غير المسموحة، الربط بالرسائل، منع التنزيل لغير الأطراف.
- Edge Functions: حذف الحساب مع ملفاته، حماية حساب المالك، ووصول سلسلة الإشعار من القاعدة حتى استدعاء Expo.
- استعادة كلمة المرور بالرمز عبر البريد.
- تشغيل التطبيق نفسه (هدف الويب) واختبار الرحلة كاملة: تسجيل ← طلب ← محادثة ← استشارة ← إشعارات ← دخول المالك ← رد ← تغيير الحالة ← نشر مشروع ← الوضع الليلي.
- تجميع حزم Android وiOS بنجاح (`expo export` إلى Hermes bytecode)، وتوليد المشروعين الأصليين (`expo prebuild`) مع RTL والروابط العميقة واسم «فهدار» العربي.

**لم يُتحقق منه في بيئة التطوير هذه** (يحتاج أجهزة/حسابات حقيقية):
- البناء الأصلي النهائي (APK/IPA) — يتم عبر EAS بالأوامر أعلاه.
- وصول إشعار Push فعلي إلى جهاز (خادم Expo Push غير متاح من بيئة الاختبار؛ السلسلة حتى لحظة الإرسال مختبرة).
- التشغيل على أجهزة iPhone/Android حقيقية — يُنصح بتجربة نسخة `preview` قبل النشر.

## ملاحظات مهمة

- **محتوى فهد الحقيقي**: الملف الشخصي، المشاريع، الإنجازات والتحديثات تبدأ فارغة ويُدخلها فهد من لوحة الإدارة. التطبيق يعرض حالة «لم يُضف بعد» بدلاً من أي بيانات وهمية.
- تغيير اللغة يعيد تشغيل التطبيق تلقائياً لتطبيق اتجاه RTL/LTR.
- لتعديل الألوان: `src/lib/theme.ts`. لتعديل النصوص: `src/lib/strings.ts`.
- لإعادة توليد الأيقونات بعد تعديل الشعار: `npm run icons`.
